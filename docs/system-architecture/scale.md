# 水平扩展

水平扩展是通过增加服务实例或工作节点提升容量。扩展前先确定瓶颈是前端请求、数据库、对象存储、队列还是评测计算；只增加 Web 实例无法解决队列积压或单个数据库的容量限制。

## 常见扩展方式

- **前端与后端**：将无状态实例放在负载均衡器后；会话和共享状态移到数据库或缓存。保证部署版本兼容并支持逐步发布。
- **评测机**：增加独立工作节点，按语言运行时、CPU 架构和数据位置标记能力。自动扩容时应设置上限，避免资源成本失控。
- **队列**：按任务类型或优先级分区，评估顺序保证、重试和公平性；队列分片后需考虑热点分区。
- **数据层**：先通过索引、连接池、读副本和对象存储减轻负载；分库分片会增加事务、查询和运维复杂度，应以测量结果为依据。

扩容需要同步容量规划：最大并发、内存、磁盘临时空间、网络带宽和数据库连接数。通过压测和渐进发布验证吞吐及延迟，并保留节点排空与任务迁移流程。集群健康状态见[可观测性](observability.md)。
