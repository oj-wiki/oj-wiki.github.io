# 评测队列

评测队列将 Web 提交请求与执行代码的评测机解耦。后端写入提交和待评测任务，调度器选择合适的在线评测机，评测机完成后回传结果。队列让系统能够缓冲高峰并独立扩容，但消息系统本身不能替代任务状态数据库。

## 调度策略

- 按赛事、用户或任务类型设置优先级，并避免低优先级任务长期饥饿。
- 根据语言运行时、数据位置、节点能力和负载选择评测机。
- 限制单用户并发和整个集群的并发，防止资源被少数任务占满。
- 对失败任务设置重试次数、退避间隔和死信/人工排查路径；程序本身 WA、TLE 等正常结果不应当作队列失败重试。

## 交付与一致性

实际系统可能重复投递或在确认消息前崩溃，因此消费者应使用任务 ID 做幂等处理，并将“已领取、运行中、完成、失败、取消”等状态持久化。任务应包含不可变的题目数据版本和限制配置；重测则创建新任务版本，避免旧结果覆盖新结果。取消任务必须通知评测机终止整棵进程树并回收资源。

监控队列长度、最老任务等待时间、领取失败、重试率和各节点吞吐量。若队列持续增长，应先定位是调度瓶颈、评测机容量还是任务耗时变化，再扩容或调整策略。参见[可观测性](observability.md)和[评测机](judger.md)。
