# 缓存

缓存用于减少可重建数据的重复读取，或保存适合短期共享的状态。它不是权威数据源：缓存丢失或清空后，系统应能从数据库、文件存储或队列恢复必要状态。

## 常见用途

- 登录会话、短期验证码和限流计数。
- 热门题目元数据、榜单片段和只读配置。
- 评测队列或分布式锁等协调状态（只有在所选缓存系统提供相应一致性语义时）。

题目测试数据和用户提交文件通常应放在有持久化、权限控制和备份策略的文件存储中；评测节点可建立本地缓存副本以减少下载延迟，但应按题目版本或内容摘要校验，避免修改题目后继续使用旧数据。

## 一致性与失效

缓存更新需要明确采用写穿、旁路读取或失效通知等策略。设置合理 TTL、容量上限和逐出策略，并在数据变更时失效相关键。缓存不可用时，后端应根据业务重要性选择降级、限流或拒绝请求，避免所有请求同时回源导致数据库过载。不要在缓存中长期保存唯一副本的评测结果或比赛最终成绩。
