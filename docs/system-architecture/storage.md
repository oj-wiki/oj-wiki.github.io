# 数据存储

OJ 通常同时使用关系型数据库和文件存储。数据库保存用户、题目元数据、比赛、提交状态与权限关系；文件存储保存源代码、题面附件、测试输入输出、checker 和编译产物等大对象。

## 数据边界

- 数据库事务适合维护需要原子更新的结构化状态，例如提交记录和比赛配置。
- 对象存储或受控文件系统适合保存大文件；数据库只保存对象标识、大小、摘要和版本等索引信息。
- 队列保存待处理通知或任务，但任务的最终状态应有可查询的持久化记录。
- 临时目录、构建缓存和评测机本地数据可以丢弃，需与唯一持久副本区分。

文件名不能直接作为可信路径使用。上传和导入时应限制大小、校验路径、拒绝目录穿越，并由服务端生成存储键。评测机下载题目数据时应校验版本或内容摘要，并限制只读取任务授权的数据。

## 备份与生命周期

备份范围需要同时覆盖数据库和文件存储，并保证两者的时间点和对象引用一致。定期进行恢复演练，检查题目、代码、附件和比赛状态都能恢复。按保留策略处理过期提交与临时文件；删除操作应考虑软删除、审计和恢复窗口。对象存储的版本控制、加密和访问策略需按平台需求配置，不能把公开对象 URL 当作访问控制机制。
