# 记分策略

评测结果由测试点结果和题目配置的计分规则汇总得到。题面应说明总分、测试点分值、分组依赖及最终分数的计算方式，避免参赛者只能从评测结果猜测规则。

## 常见策略

- **二元得分**：全部测试通过才得满分，否则为零，常用于传统题和 ICPC 赛制。
- **逐点部分分**：每个测试点独立计分，按通过或 checker 返回的分数累计。
- **分组计分**：一组测试点需整体通过才获得该组分数；适合表达算法子任务或数据范围层级。
- **自定义评分**：checker 可根据输出质量返回分数，适用于优化题等；应限制返回范围并定义非法输出的处理方式。

## 配置注意

测试点分值之和通常应等于题目满分。若测试点有依赖，应明确依赖规则；失败、超时、运行错误和格式错误如何影响得分也应保持一致。使用浮点分数时，应规定精度和舍入行为。

## 发布前核对

- 用小型例子手算各测试点和子任务的最终分数，并与 OJ 实际结果比对。
- 明确未运行、编译失败、超时、运行错误及 checker 错误时的计分规则。
- 子任务应避免循环依赖；若一个子任务依赖另一个子任务，题面和评测配置都要使用相同关系。
- 对动态分数或优化题说明分数范围、无效输出处理、舍入方式和并列规则。

计分规则应与测试点组织一起版本化。重测可能改变已有成绩，赛事期间应按规则公告变更并保留旧版评测记录。
